# Python helpers

The PDF, OCR and HEIC work that Python does better than JavaScript. Each helper runs as its own process, started by `src/features/conversion/engines/pdf-python` and `heic-python` through `runHelper` (`engine-kit/python.js`); nothing here is linked into the app.

The packages are in `requirements.txt`. The in-app installer, `npm run setup:pdf` (`tools/setup-pdf-engine.ps1`) and `tools/make-notices.js` all read it. PyMuPDF is pinned: its 2.x releases pull in a 120 MB layout-analysis stack that nothing here uses. The code runs on Python 3.9 to 3.13.

## Entry points and libraries

An entry point is run with `python -W ignore <script> <arguments>`. Libraries are imported by entry points and never exit the process.

| File | Kind | What it does |
|---|---|---|
| `pdf_to_docx.py` | entry | PDF to editable Word: `<in.pdf> <out.docx>` |
| `pdf_to_text.py` | entry | PDF to Markdown, HTML or plain text: `<in.pdf> <out> <md\|html\|txt> [images folder]` |
| `pdf_to_tables.py` | entry | The tables of a PDF as JSON for the Excel writer: `<in.pdf> <out.json>` |
| `pdf_to_layout.py` | entry | Text with exact positions, plus background pictures, for the PowerPoint writer: `<in.pdf> <out folder>` |
| `image_to_heic.py` | entry | An image to HEIC: `<in image> <out.heic>` |
| `ocr_warmup.py` | entry | Loads the OCR engine once so its models download during the install |
| `helper.py` | library | `require()`, `progress()`, `exit_no_text()` and `run_pdf_job()` |
| `pdf_ocr.py` | library | Reads scanned pages with RapidOCR into a temporary PDF with real text; the faint show-through of the other side of a sheet is not written, and a line slanted against the others (a stamp) is written invisibly |
| `pdf_spans.py` | library | What the readers share: `hexcolor`, `BAD_XML`, `TEXT_FLAGS`, `has_unmapped_symbols`, `dominant_size`, `dedupe` |
| `pdf_fonts.py` | library | PostScript font names to Word font families, the fonts Windows has installed (`installed()`), the installed family closest in width to a font it lacks (`stand_in()`), and which spans are mathematics (`math_font()`) |
| `pdf_flow/` | library | PDF to Word (see below) |
| `pdf_structure.py` | library | Reading order, headings, lists and tables, written as Markdown, HTML or text |
| `pdf_layout.py` | library | The exact-position reading for PowerPoint |

`pdf_flow/` is the Word converter, split by responsibility: `common.py` (units, escaping, box geometry), `lines.py` (spans to lines, list markers), `shapes.py` (pictures, rules, boxes, tables), `fonts.py` (text measuring), `maths.py` (built-up equations), `page.py` (one page), `builder.py` (laying out a region), `lists.py` (numbering), `structure.py` (styles, contents, headers and footers) and `convert.py` (the page loop). Imports only point downwards in that order. `pdf_flow/__init__.py` exports `convert`. A rotated page is read upright (`open_upright`) and written as one text box the size of the shown sheet, turned back (`turned_page` in `builder.py`), so its text stays text and its sheet keeps its size and orientation; when `page_kind` calls such a page a design page, `design_page` writes it with its picture turned and each line a turned text box, and its tables stay in the picture, the words of a justified line that the PDF stores one by one are joined (`stretched_row` in `lines.py`), the pictures of a page are anchored in its first paragraph or first table cell, and a wide picture at the foot of a page is placed on the page together with its caption (`ends_page` in `convert.py`). Text in the bottom tenth of an upright page, well clear of the rest, and a picture that gridlines cross or that text wraps right up against are placed on the page as well, so Word laying the text a little taller never moves them to a new sheet. The placed paragraphs of a page (frames) are written before its running text, because Word puts a frame on the sheet where its paragraph falls, and a line in the last 5 % of a sheet is placed as well. A box, a row or a table that reaches the foot of the sheet stops 4 pt short of it (`above_foot` in `builder.py`), because the paragraphs Word must write after a table, and the section break in the last of them, would otherwise start a new sheet. Text is read down to 1 pt, the smallest size Word can set, so the labels a slide print shrinks to stay in the file (`span_ok` in `lines.py`). A paragraph in a table cell keeps no spare room on its right, and a line that fills its cell is set 1 twip a character narrower, because Word clips what overhangs a cell (`room` and `edge` in `builder.py`). A font Windows does not have is written as an installed serif, sans or mono family of about the same width (`stand_in` and the installed list in `pdf_fonts.py`, used by `FontMeter` in `fonts.py`), and a line Word would set wider than the PDF is condensed by at most 0.8 pt a character (`span_run` in `page.py`). A table row taller than half a sheet may split across sheets (`keep` in `builder.py`). A table drawn as an outer colour with a lighter rectangle inset in each cell is read as one table: the thin strips between the two are not cells (`tables` in `page.py`). The columns of a ruled table are the positions of its rules, not the edges of its fills, because Word draws a shaded cell as a fill the size of the cell and another inset by the cell's padding (`rule_edges` in `page.py`). A cell's fill is the last fill drawn that covers most of the cell and lies inside the table, whether the PDF drew it for the cell, the row, the column or the whole table; the colours of the table's own fills, and the soft edge where they meet paper or each other, are taken out of the page picture (`leftovers` in `page.py`). Whatever else is inside a table (a bar across several days, an icon, the part of a shaded row that has no cell) stays a picture behind the table at its place on the sheet (`under_table` in `convert.py`). Strokes and thin bars that are not a border or an underline (a signature line, a separator) are line shapes anchored to the sheet at their place, touching pieces joined into one; a border of a table or box, anything inside a table, and anything inside a picture is not written again (`free` in `convert_page`). Shaded bands that stand a row apart, such as a statement shaded every other row, with the rows between them are one table (`stripes` in `builder.py`): a gap as tall as a band that holds text is a row left unshaded, the row after the last band is kept, and a line that crosses the columns, such as a month heading, is a row across all of them. Marks in the outer 8 % of the sheet's width with no text on them (mailing and sorting bars) are placed on the sheet and are not a column of the page (`in_margin` in `convert.py`). Word adds half the width of a rule to each of the two rows beside it, so a table's rows are written that much shorter (`edge` in `table`). Rows made only of a text and a figure after it, repeated three times or more (an index with page numbers, a price list in columns), are one line each, with a tab at the figure's right edge (`end_figures` in `lines.py`). A bar at most 6 pt thick along the whole of one edge of a box, over it or just outside it (the box then reaches out to it), is that side of the box's border (`edge_bars` in `page.py`). A rule below everything else on the page is a line shape on the sheet and not a paragraph with a long space before it, which a page that comes out a little taller in Word would push onto a new sheet. A box with rounded corners (four quarter-circle curves of at least 3 pt, `corner_radius` in `shapes.py`) keeps its text in the one-cell table with no fill or border of its own and has a `roundRect` shape behind it with the box's fill and border, anchored in a paragraph just above the box so that it moves with the box's text (`shape_xml` in `builder.py`); a rounded box inside a table cell stays square, and on a design page the page's own picture already has the corners. A picture that a filled shape is drawn over later, such as a caption band, is cut from the rendered page instead of taken from the file, which has no band (`overdrawn` in `page.py`, from the page's bbox log). The gap between a rule and its text is the table's cell padding, and what the cells of a table share (the rule, a shaded header row, stripes, a first column) is written once as a table style, `PDF Table 1` and so on in `styles.xml` (`table_look` in `shapes.py`, `table_style` in `structure.py`), so a cell states only what differs from it, the header row repeats on the next sheet, and Word's Table Design boxes (Header Row, Banded Rows, First Column) and its gallery work on it. The margins are also written on the table, so that they stay when another design is chosen. A cell with nothing in it that is tall enough for a line holds an ordinary empty paragraph, so text typed there shows and the row grows (`blank` in `builder.py`). A centred paragraph gets no first-line or hanging indent. Letter spacing is read from where the letters of a span start, which `read_lines` keeps from PyMuPDF's raw text (`letter_step` in `page.py`): the median over neighbouring letters of the step minus the letter's own width, written only when two letters agree within 0.1 pt, and never from the span's box, which holds a removed list marker, trailing spaces and side bearings. A frame that holds one line inside the text column has no width, so Word sizes it to its text; one outside the column (a footer at the right edge, a line beside a narrow column) is 10 % wider than its line, because Word cuts an automatic width at the margin; a frame or a text box of several lines is as wide as the longest line plus the letter spacing written and 3 pt (`spacing_written` in `builder.py`). The labels of a chart on a document page (five or more short pieces on a drawing, none of more than five words) are positioned paragraphs on the picture and are cut out of it (`chart` in `convert_page`); so are the tick labels around a plot that holds a label of its own, three or more short pieces one under another (the same left or right edge) within 30 pt of the drawing, whose curves would otherwise leave their numbers as lines of the text beside it. A text, a run of leader characters and a short end piece, or a dotted or dashed stroke on the baseline between two pieces of a row, is a paragraph with a right tab that carries the leader, so it cannot wrap when Word sets the text a little wider (`split_leader` in `lines.py`, `stroke_leaders` in `page.py`); the leader characters are not written, and such a line is not a short piece when the page class is chosen. A page longer than 22 inches (1584 pt) on a side is placed, scaled to fit with its proportions, on a page of that size before anything is read (`fit_sheets` in `convert.py`), so its text is still text and its links stay, and its annotations print only through the picture. The last letter of a letter-spaced line that fills its cell is a run of its own without the spacing, which Word adds after the last letter and wraps on (`span_run` in `page.py`). Outlined boxes with a gap between them stay separate boxes with four sides, not the rows of one table (`stripes` in `builder.py`), and the edge of an outlined box is not also written as a rule. A number that opens a paragraph whose next line starts under the number, as in `(1) The Supplier ...`, is text, not a list item (`hangs` in `lines.py`). A bullet is made only of bullet characters, and the letter `o` counts only on its own, so a line that starts with `of`, `on`, `or` or `one`, or a first cell such as `-sU `, keeps its text and is not joined to the cell beside it (`bullet` in `lines.py`). Running text in two or three columns is a continuous section with Word columns, with a column break in a paragraph of its own where the columns end at different heights (`column_runs`, `settle`, `numbered` and `columns` in `builder.py`, `end_sections` in `convert.py`); a large letter beside the first lines of a paragraph is a Word drop capital (`capped` and `drop_cap` in `builder.py`, kept apart from the line beside it by `is_drop_cap` in `lines.py`); a page can therefore hold several sections, `convert_page` returns the header and footer of each, and `attach` in `structure.py` gives references only where they change. A page set freely over pictures and colour is a design page (`page_kind` in `page.py`; what counts as covered is what pictures, box fills and figures paint, the ink of a figure and not its box, leaving out the shaded rows of a table drawn without lines and the fill of a box that holds running text; a figure over 40 % of the sheet with short labels on it is a design page too; short pieces of text count by their words, more than half of them, leaving out three or more lines under each other, equation rows, and pages whose only art is shaded rows or ruled lines) and has no flow: `design_page` in `convert.py` renders the page without its text as one picture behind everything and writes each paragraph as a text box anchored to the sheet (`text_boxes` in `builder.py`). The boxes are written in the order the PDF wrote the text when that reads like a page, at least 80 % of the steps going down, along a row or on to the right (`written_order`, from the place each line has in the PDF, `seq` in `lines.py`), because Word prints text boxes in the order they stand in the file; otherwise they are in a geometric reading order (`reading_order`). A table on a design page is a Word table placed on the sheet (`placed` in `table` in `builder.py`: `tblpPr` anchored to the page, overlap allowed, rows `atLeast`, a single line no taller than the table's shortest row, because Word's own line height for the font can exceed the PDF's row pitch): a ruled table comes from `tables` in `page.py`, three or more rows of text that line up in the same columns with no ruling and that the PDF wrote as one text block come from `aligned_tables`, and the rules and cell colours the table paints itself are taken out of the page picture when `table_art` can tell them from the rest of the drawing, otherwise the page keeps them and the table has no borders or shading. On a flowing page, lines side by side that the PDF wrote across, a label and then its value, are one tabbed paragraph a row, and lines that it wrote down one column and then down the next are the cells of one row, however wide each line is, so Word reads them in the PDF's order (`across` and `laid` in `builder.py`). A line of text turned at any angle, a side label or a stamp, is a text box turned by the same angle and anchored to the sheet, on any page (`turned_text_box` in `builder.py`), and is taken out of the picture it was part of, so what surrounds it, such as a stamp's frame and colour, stays in the picture and the words are text on top (`mark_text` in `convert.py`). Lines set further apart than two lines still run on as one paragraph when a third keeps the same rhythm under the same left edge and the one above reached the right edge, which is double spacing and ruled paper (`joins` in `builder.py`). A paragraph that wraps in places and has a line break in others (an abstract above its keywords) has the width of the PDF's lines as its right indent, so Word wraps it in the same places (`reflow` in `para_xml`). A line ends where the PDF's does unless the paragraph is justified, and a left-aligned box does not wrap, so a wider substitute font cannot break a line; text that is only pixels in a picture stays in the picture. A scanned page and a page with no text stay document pages. `pdf_to_docx.py` hands `convert` the original PDF beside the OCR copy (`original`), because the copy holds only the recognised text: for a page that needed OCR, the picture of the scan is rendered from the original, the lines that become text are painted out of it in the colour of the paper around each (`scan_page` and `paper` in `convert.py`; a page that is one picture over most of the sheet with an invisible text layer, or text drawn under the picture, is a scan with a layer (`text_layer` in `page.py`): its invisible text is read, the picture is the page itself, and no OCR is run (`page_needs_ocr` is false for it, as it has text). A large line stays text when it is wider than four times its height, holds two words of letters and stands on plain paper in grey or black ink (`plain_title`); when the lines share one angle under 2 degrees they are written level about the page's centre (`straighten`) and painted out along their own slant (`paint_quad`); a mark of one or two characters that is not a word, alone in the outer tenth at the top or left, is left in the picture. The layer is trusted as it is, so its misreadings stay, but a scanner sizes each word by its own box, so a line of the layer is set in the size most of its letters have (`even_sizes`), a piece that starts within a word space of another stands on that one's row, because a recogniser that splits a line gives its pieces baselines of their own, and the rows that levelling brings together are joined again; a line is cut a little higher than its box by up to 1.5 % of its width, because OCR text sits at the foot of the box of a skewed line), and it lies behind the text as a picture the size of the sheet. A line larger than 1.6 times the body size, a logo, a signature, a stamp or a large heading, is not text and stays in the picture, and so does a line with colour in its ink (`inked_in_colour`: a stamp, or a pen's writing) or that is slanted against the others, and so do the rules and the paper; the words of such a line are written as hidden text (`keep_in_picture`), so that search finds them. A photograph, a page slanted by 2 degrees or more, a page a quarter of whose lines are more than a degree off the rest, or one whose paper's light differs by more than a tenth across the sheet (`lean` in `pdf_ocr.py`, `uneven`), keeps its picture whole and all its words are hidden text, and so does a page stored with `/Rotate` that carries a layer. In `pdf_ocr.py`, text whose ink is less than 40 grey levels darker than its paper is the other side of the sheet showing through and is not written Recognised text has no font: it is set in the default family and is not bold. A line in the top or bottom tenth of the sheet whose text repeats on at least three quarters of the pages, with the numbers that are the page number and the page count read as `PAGE` and `NUMPAGES` fields, is not written in the page: it is a framed paragraph in a header or footer part (`Furniture` in `structure.py`), and a section carries references only where its header or footer differs from the section before it. A picture of the same image at the same place (within 2 points) in the top or bottom tenth of at least three quarters of the pages is written once in the header or footer part, anchored to the sheet and related from the part (`logo` in `Furniture`, `attach` in `structure.py`), and is left out of those pages. A header or footer in a table, a box or a design page, and one whose numbers are not the page number, stays where it is. The styles are written by `set_styles` in `structure.py` with no look of their own, so a run states its font and size only where they differ from Normal (`span_run` in `page.py`): a heading is Heading 1 to 3 by its size unless it is spoken or signed text: more than two lines or twelve words, a quotation mark at either end, a sentence of more than six words that ends in a full stop, or a name of up to three words under a closing such as `Yours sincerely` (`said` in `builder.py`); the first large heading of the first page is Title, a short bold line of body size on its own above plain text, outside a table or a design page, is Heading 3 (`labels` in `builder.py`); neither is a heading in a table, without a letter, or in a look (font, size, weight, colour) that the page uses more than eight times or three times on one row, as the cards of a grid, the products of a list and the days of a calendar do (`heading_ok`), a list item is List Paragraph and a line such as `Figure 1. ...` is Caption (`para_xml` in `builder.py`). A paragraph's lines are `atLeast` the PDF's pitch where Word's own height for the font (`line_height` in `pdf_fonts.py` reads the ascent, descent and line gap from the installed font, which is how Word sizes a line) is no taller, or where the pitch is 1.32 times the size or more, so they make room when the text is made larger (`line_rule` in `builder.py`). Where the PDF sets them tighter than the font, where sizes in the paragraph differ by more than 8 %, where the text is not Latin or where the font is not installed, a paragraph that is not placed is a multiple of Word's own line height (`auto`, so it follows a change of font size) and one in a text box or a row of a placed table is `exact`. LibreOffice sizes a line differently from Word, so lines set as a multiple can sit a little apart there. A line that ends at the hyphen of a word the text spells with a hyphen elsewhere keeps it when Word sets the paragraph again (`compound` in `builder.py`). The paragraph that closes the last page is an ordinary empty paragraph, so text typed at the end of the document has the body size, except on a page that ends in columns, where it is one point high because a line of body height after columns that fill the sheet would be a sheet of its own; the closing paragraphs of the other pages are one point high because they end a section (`close_page` in `convert.py`). Every drawing id in the document comes from one counter (`Lists.drawing_ids`), so no two pictures or text boxes share an id however many there are on a page. If the sections a page adds ever differ in number from its header and footer states, `convert` pads or trims the states and `attach` puts the header and footer in the first section, and both log it, so the lines taken out of the pages are not lost. `POMELO_DEBUG=1` prints each paragraph's alignment and whether each page is a design page or a document page (`page_kind` in `page.py`) and which order a design page's text boxes are in. It lists the lines that were read and never written (a line joined into another counts as written, through `Line.parts`), the figures found inside tables and every line of light text that has no cell fill, box fill, highlight or picture under it (`light_text_check` in `convert.py`), because Word has no page behind the text and such a line would print white on white. Text the PDF does not show is kept as hidden text (`w:vanish`), so the page looks as the PDF does and the words are still in the file: text in the invisible render mode, text under an opaque rectangle drawn after it, and text in the colour of the flat ground under it (`hide` in `page.py`, found from the text trace, the drawing order and the page with that text taken away). A line with only hidden text is not part of the layout (it cannot move visible text or change the page's class) and is written as hidden paragraphs at the end of the page (`hidden` in `builder.py`). Text in a clip render mode paints nothing itself and is not in the trace: the picture shows through its letters, so it is not read and stays in the picture. A page that is one big picture is a scan and has none of this: its invisible text layer is read as text instead (below). Every upright line is taken out of the picture the turned text of a stamp or watermark is cut from, wherever the turned word's bounding box lies, so a watermark across a paragraph does not leave the paragraph printed twice. Zero-width characters (U+200B, U+2060, U+FEFF) are dropped where a span is read, before a marker, a leader or a join is decided, because Google Docs writes each bullet as the glyph followed by U+200B (`read_lines` in `lines.py`); U+200C and U+200D stay, as they shape Persian and Indic text. The left margin of the flow, and the left edge of a table found from drawings that has no rule there, start where a list number does and not where its text does (`Line.left`, `tables` in `page.py`), so a numbered paragraph's indent is the gap to its text and its hanging indent is the width of its number. A list item on its own line is never centred or right-aligned by where its text ends, only by where its number starts, and in a table a cell whose line runs past its right edge takes the empty cell beside it, so Word does not wrap the line (`table` in `builder.py`). Each numbered item written in a text box gets a numbering definition that starts at its own number, because a text box is a story of its own and does not continue the list before it (`Lists.item`). The pieces of a leader line are cut where their letters start and not in proportion to their characters (`letter_x`), so a title keeps its width and is not condensed; in a row of pieces, a piece with a leader gets a left tab at its start and a right tab with the leader at its end (`tabbed_para`). A bold section number and the bold title after it in the same size, up to one and a half sizes apart, are one line with a tab after the number (`heading_number` in `lines.py`), and `para_xml` writes a tab stop for every tab it holds. A run of three or more contents entries (paragraphs with a leader tab and a page number after the last tab; a rule, a page break or a short running foot between two pages of one list does not end it) whose titles are, in order, the text of paragraphs that carry no style but a heading one is a Word table of contents field (`contents` in `structure.py`): the entries stay as the PDF shows them and each links to a `_Toc` bookmark on its heading, the heading gets the Heading style of the entry's level (the indents of the entries give up to three levels), the styles TOC 1 to TOC 3 hold the tab stops and indent of the first entry of each level so that Update Table keeps the look, and a title "Contents" above the list is TOC Heading so that it is not listed. A list where one entry matches no paragraph, or that has more than three levels, stays plain paragraphs. Each entry of the PDF's own outline puts a bookmark (`section_1` and so on) on the paragraph that holds its title. The table finder keeps a grid when the shading of one of its rows or columns runs on past it, as the header band of a sheet wider than the page does: a band that lies on the edges of its rows (or of its columns) and covers the whole grid is not a box sticking out (`tables` in `page.py`). A grid that a path of ten or more curved or slanted segments (`bent` in `shapes.py`) overlaps by a fifth of its area is the frame and gridlines of a plot, and is left a drawing. When the rules over and under a grid run past its first vertical rule with at least two lines of text between them, the table starts at the left end of those rules and that column is a column of the table (`label_column`), as in a LaTeX table set `l|cc`. A figure found in the render of a page without its text is dropped as the soft edge of a box only when it is a ring no thicker than the 4.5 pt the box may be off by, so chevrons and other filled shapes that share a box's outline stay in the picture (`leftovers`). A path of several rectangles or closed runs of lines whose areas fill less than 86 % of its bounds, the bars of a chart drawn as one path, is not one box (`piece_areas` in `shapes.py`). A table cell that spans several columns only because a fill ran across them, as the shading of a row does, is a cell for each column when its text stands in two or more of them and none of it crosses a column edge (`split_cells` in `page.py`), and a line that runs from one cell into the next is cut where the next cell starts, on a space or a gap wider than a letter (`cut_at_cells` in `lines.py`). A picture in a table cell that stands on the same row as a line of text in that cell, such as a data bar, is set behind the table at its place on the sheet like the art inside a table, because in the cell it would add a line to the row. A picture laid over another keeps its place on the sheet, and so does a picture within 3 pt of one of those, such as the colour scale of a figure, which set in the line would take room under the figure. A cell border drawn twice, as a stroke and as a thin rectangle, uses up both drawings, so the copy is not written as a rule inside the cell. A line of text with no letter in it that stands in a small outlined box, a chart or an infobox, is not counted by `page_kind` as a piece set at a point. The letters a clip path cuts off are found by reading the page's text with and without `TEXT_CLIP`: a run is split at them (`clipped_runs` in `lines.py`) and the cut part is a hidden run (`w:vanish`), so the whole text stays in the file and only what the PDF shows prints. Letters cut by the sheet's own edge are not clipped runs. A picture or a box at the left or right edge of the column, with its caption under it, that the lines of a paragraph run beside and that the same paragraph carries on past above or below it at full width, is a drawing anchored in that paragraph with square wrapping, and the paragraph is one block of text across the column (`wrapped` and `float_xml` in `builder.py`): a picture alone is an anchored picture, and a picture with its caption, several pictures side by side or a box is a text box that holds them as they stand and resizes to its text; the text keeps the distance from the drawing that the PDF has. A box with three lines or more beside it is wrapped without the paragraph carrying on, and a picture whose text stands apart from the rest stays a table row. Lines shortened by a drawing are written at the full width of the column and are not broken at their ends. Wrapping is used only on running text outside columns, tables and boxes. A highlight drawn behind a few letters of a span splits the span at the highlight's edges and is shading on those letters, not a shape left behind (`cut_at_rects` in `lines.py`). The lines beside a large first letter may start inside the letter's own box, since its advance is wider than its ink, and the drop capital covers as many lines as stand beside it. A line that ends at a hyphen keeps it when it stops short of the paragraph's right edge, and a number such as forty-five keeps it anywhere; a hyphen at the end of a justified line is taken as the break of a word (`compound` in `builder.py`). Word breaks lines greedily and without hyphenating, so a paragraph that the PDF set with hyphens came out a line longer; when at least 10 lines of the first 60 pages, and at least one in 67, end at a hyphen in front of a lowercase word, the file turns on Word's automatic hyphenation (`autoHyphenation`), the Normal style sets `suppressAutoHyphens`, and only the justified paragraphs ask to hyphenate (`hyphenating` on `FontMeter`). The words of a justified line in a narrow column are joined when the line ends where other lines of the same text block end (`stretched_row`). A mark drawn over a line of text, such as an underline made of art, is placed on the page and does not split the paragraph (`drawn_on` in `convert.py`). A piece in a row of tabs that stands further than four fifths of a size from the piece before it and ends within about half a size of the right edge is on a right tab, so a wider font cannot wrap it inside a word. The footnotes of a page of running text are Word footnotes (`find_notes` and `apply_notes` in `page.py`, `add_notes` in `structure.py`): a block of lines under a short rule, or under a gap of more than a line, set smaller than the body, each opening with a number, a symbol or a letter that also stands raised in the text above, is a note in `footnotes.xml` (styles Footnote Text and Footnote Reference), and its mark in the text is a footnote reference, so Word keeps the note on the page of its reference. A mark that is the number Word would give the note is Word's own; one that is not (a symbol, a number that starts again on each page) is written as a custom mark. Two marks that stand together as one raised span are matched to two notes. A note that goes on from the page before, or whose mark is not found in the text, stays a paragraph, the rule is not drawn because Word draws its own separator, and a design page, and a page that is set in Word columns (Word lays a footnote out badly under columns), keep their notes as text; the page is written again without its notes when its columns are found. A page with notes ends its text above its own footer. Endnotes (a list of notes at the end of a document) are not made.

## How a helper runs

Every entry point starts with `import helper`, then `helper.require(...)` for the packages it needs, then runs `main()` under `if __name__ == "__main__"`. For a PDF, `helper.run_pdf_job(src, work)` does the common part: a scan is read with OCR first (the first 70 % of the progress bar), `work(path, progress)` runs on the PDF, a failure becomes a one-line reason, and the temporary OCR copy is deleted. `work` must close every document it opens before it returns, because Windows will not delete a file that is still open.

## Contracts

The Node side depends on these (`test/integration/python/cli-contract.test.js` checks them):

- Arguments as in the table.
- `POMELO_PROGRESS <0..1>` lines on stdout while it works, and `OK` at the end.
- On failure, one line on stderr and an exit code: 1 failed, 2 a component is not installed, 3 the PDF has no text to convert.
- The messages for a password-protected, a damaged and a page-less PDF, and for a scan when OCR is not installed. The tests assert on them.

## Testing

`node test/run.js --tier=pdf` (needs the PDF engine): the command-line contract, the Word layout checks (`pdf-layout`), and the other formats (`pdf-formats`). For real pages, `npm run test:fidelity` scores PDF to Word against `test/fidelity/baseline.json`; any change to `pdf_flow/` must leave every sample's score equal. `node test/fidelity/run.js --word` does the same comparison with Microsoft Word as the renderer (see `test/README.md`).

## Known limits

- Text in columns is written as Word columns only when it stands in two or three columns with the same gutter, holding lines, inline pictures, tables, boxes, centred captions and equations with their number; anything that crosses a gutter ends the run, and columns beside a rule stay table cells. Columns that end within one and a half lines of each other are left to Word to balance, so text typed at the foot of one runs on into the next; columns that end at different heights keep a column break, and text typed there does not run on.
- A drop capital is a Word drop capital only on a page of running text. On a page set freely over pictures it stays a text box at its place, because Word does not wrap text round a drop capital inside a text box.
- On a design page, a table with no ruling is found only when its rows share one PDF text block and every cell starts at a left edge shared by three lines; a row whose text runs into the next column, or whose first cell was joined to the next one as if it were a list marker, stays a text box and ends the table. Word prints the text of a placed table before the page's text boxes, so a text-order check reads it first. A page that is flowing text and stands sideways (`turned_page`) is read top to bottom, so a form the PDF wrote in another order, with its signature line before its fields, is read in the page's order and not the PDF's. A row added to a table that sits on a coloured panel extends past the panel, and the new row has no panel colour under it. Text drawn with transparency, such as a stamp or a watermark, keeps its transparency in Word 2010 and later (`w14:textFill` with an alpha, which older readers ignore), and a translucent fill over paper or a flat colour is written as the colour it makes there, since cell and box shading has no transparency (`blend` in `page.py`); a fill under a quarter opaque is a shadow or a glow and stays in the picture, and so does a fill over a picture or over a ground that is not flat (`blend` drops it from the shapes, so it is neither a box nor a table). Text in a Type3 font, which has no font name, is written in the default face, so a bold sans heading in such a font comes out in a plain serif.
- A header or footer moves into its part only when it is the same on most pages: one that is not, or whose number is not the page number, stays on the page, and so does a logo that moves, or one that sits in a table, a box or a design page. A part holds the value of one page in its page field, so a reader that does not work fields out shows that number on every page; Word works it out when it prints.
- Mathematics: a span of mathematical letters (U+1D400 to U+1D7FF) or in a symbol font of a TeX paper (`CMSY`, `CMEX`, `MSAM`, `MSBM`, `rsfs`, anything named Math) is written in Cambria Math; plain letters in an italic maths font (`CMMI`, `LMMathItalic`, `txmi`) are italic text in the stand-in family, because Cambria Math sets them upright outside an equation object. Built-up mathematics (pieces stacked on several baselines: a fraction, a root, a sum with limits, a matrix, found by `maths.py` as lines that touch or a fraction bar between them, with a mathematics font among them) is written as an inline picture cut from the page, lowered so that the equation's own baseline lies on the line's, with its text kept after it as hidden text so that search finds it; an equation number at the right is a tab and text in the same paragraph. The picture takes the place of the equation's spans in the line of running text it stands in, or is a line of its own. An equation set in an ordinary text font, with no mathematics font in it, and equations on one baseline stay text; equations are not rebuilt as Word equations.
- Right-to-left text: a paragraph whose letters are mostly Arabic or Hebrew is a Word right-to-left paragraph, its lines joined when they end at the same right edge, its runs written in reading order, and Arabic presentation forms are written as the letters they shape (Word shapes them again). A justified Arabic or Hebrew line that the PDF stores word by word is not joined into one line.
- Form fields on a page that flows: a check box or a radio button is one character in Segoe UI Symbol (☐ ☒ ◯ ◉) in a frame at the field's place on the sheet, and a box drawn as a square next to a label is a list marker of the same character. A text area or a list box with a border gets a shape behind the text. The fill and the text of a field are the page's own. Signature fields and buttons are not drawn, nothing is written for a page stored rotated, and the characters sit where the PDF has the field, not in the line of text they belong to, so a taller line above moves them apart.
- Text is measured in the installed family Word will use, because the metrics in an embedded copy of a font can be those of another font; a font Windows does not have is measured in its embedded copy.
- Pieces that each stand alone on a row at the right of a block of text (the marks of a worksheet) are paragraphs in page order. Only pieces that share a row with the text beside them form a column.
- The fidelity check joins a word that is broken at the end of a line to its other half, in the source and in Word's printout (`plain_words`), because Word hyphenates in other places than the source; it leaves the running title and the footer out of the order score (see `running_words` in `test/fidelity/compare.py`) and counts them for recall; a field's value, which a PDF stores after the rest of the page, can still read in another order than the page prints it.
- Devanagari, Tamil and other scripts whose PDF has no usable text map (the font's ToUnicode table is missing or wrong) are read as the wrong letters: only the glyph shapes know what was meant, and reading them is not attempted.
- Words that are only pixels in a picture, such as the labels of a chart saved as an image, stay in the picture, so a word count on the printed Word file does not see them.
- Update Table on a table of contents made from a PDF lists every heading of the Word file: a heading found by its size that the PDF's own contents leaves out, such as the title of the document, is listed after the update, and a heading that sits in a text box on a design page is not.

- Rules and art behind a table are anchored to the sheet, so they stay put when the text above them is edited.
- Text outside the page is not read (PyMuPDF does not return it), so it is not kept as hidden text. Art inside a table does not move with the table when the text above it is edited, because it is anchored to the page.
- On a scanned page the logo, the signature, a stamp and any line larger than 1.6 times the body size that is not a title on plain paper stay pixels in the picture and cannot be edited, and the text that is written is in the default font and not bold, whatever the scan shows, but in the shade of the line's ink (`ink_colour`). A photograph keeps its picture whole and its words as hidden text, so it cannot be edited. A line in a coloured ink stays in the picture too, whether it is a pen's writing or coloured print, so a heading printed in colour on a scan is not editable; handwriting in black or grey ink on a flat scan is written as text like print, because neither the OCR score nor the shape of the ink tells it from print. Where a table's rules touch the text of a scan, painting the text out of the picture leaves gaps in the rules.
- The Word and the text/Markdown readers each have their own line pipeline, tuned differently (`dedupe` tolerance 3 versus 4 points, different bullet sets), so their output differs in small ways on purpose.
