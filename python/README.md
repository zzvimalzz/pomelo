# Python helpers

The PDF, OCR and HEIC work that Python does better than JavaScript. Each helper runs as its own process, started by `src/features/conversion/engines/pdf-python` and `heic-python` through `runHelper` (`engine-kit/python.js`); nothing here is linked into the app.

The packages are in `requirements.txt`. The in-app installer, `npm run setup:pdf` (`tools/setup-pdf-engine.ps1`) and `tools/make-notices.js` all read it. PyMuPDF is pinned: its 2.x releases pull in a 120 MB layout-analysis stack that nothing here uses. The code runs on Python 3.9 to 3.13.

## Entry points and libraries

An entry point is run with `python -W ignore <script> <arguments>`. Libraries are imported by entry points and never exit the process.

| File | Kind | What it does |
|---|---|---|
| `pdf_to_docx.py` | entry | PDF to editable Word: `<in.pdf> <out.docx>` |
| `pdf_to_text.py` | entry | PDF to Markdown, HTML or plain text: `<in.pdf> <out> <md\|html\|txt> [images folder]` |
| `pdf_to_tables.py` | entry | The tables of a PDF as JSON for the Excel writer: `<in.pdf> <out.json>` |
| `pdf_to_layout.py` | entry | Text with exact positions, plus background pictures, for the PowerPoint writer: `<in.pdf> <out folder>` |
| `image_to_heic.py` | entry | An image to HEIC: `<in image> <out.heic>` |
| `ocr_warmup.py` | entry | Loads the OCR engine once so its models download during the install |
| `helper.py` | library | `require()`, `progress()`, `exit_no_text()` and `run_pdf_job()` |
| `pdf_ocr.py` | library | Reads scanned pages with RapidOCR into a temporary PDF with real text |
| `pdf_spans.py` | library | What the readers share: `hexcolor`, `BAD_XML`, `TEXT_FLAGS`, `has_unmapped_symbols`, `dominant_size`, `dedupe` |
| `pdf_fonts.py` | library | PostScript font names to Word font families, the fonts Windows has installed (`installed()`), and the installed family closest in width to a font it lacks (`stand_in()`) |
| `pdf_flow/` | library | PDF to Word (see below) |
| `pdf_structure.py` | library | Reading order, headings, lists and tables, written as Markdown, HTML or text |
| `pdf_layout.py` | library | The exact-position reading for PowerPoint |

`pdf_flow/` is the Word converter, split by responsibility: `common.py` (units, escaping, box geometry), `lines.py` (spans to lines, list markers), `shapes.py` (pictures, rules, boxes, tables), `fonts.py` (text measuring), `page.py` (one page), `builder.py` (laying out a region), `lists.py` (numbering), `structure.py` (styles, headers and footers) and `convert.py` (the page loop). Imports only point downwards in that order. `pdf_flow/__init__.py` exports `convert`. A rotated page is read upright (`open_upright`) and written as one text box the size of the shown sheet, turned back (`turned_page` in `builder.py`), so its text stays text and its sheet keeps its size and orientation, the words of a justified line that the PDF stores one by one are joined (`stretched_row` in `lines.py`), the pictures of a page are anchored in its first paragraph or first table cell, and a wide picture at the foot of a page is placed on the page together with its caption (`ends_page` in `convert.py`). Text in the bottom tenth of an upright page, well clear of the rest, and a picture that gridlines cross or that text wraps right up against are placed on the page as well, so Word laying the text a little taller never moves them to a new sheet. A paragraph in a table cell keeps no spare room on its right, and a line that fills its cell is set 1 twip a character narrower, because Word clips what overhangs a cell (`room` and `edge` in `builder.py`). A font Windows does not have is written as an installed serif, sans or mono family of about the same width (`stand_in` and the installed list in `pdf_fonts.py`, used by `FontMeter` in `fonts.py`), and a line Word would set wider than the PDF is condensed by at most 0.8 pt a character (`span_run` in `page.py`). A table row taller than half a sheet may split across sheets (`keep` in `builder.py`). A table drawn as an outer colour with a lighter rectangle inset in each cell is read as one table: the thin strips between the two are not cells (`tables` in `page.py`). The columns of a ruled table are the positions of its rules, not the edges of its fills, because Word draws a shaded cell as a fill the size of the cell and another inset by the cell's padding (`rule_edges` in `page.py`). A cell's fill is the last fill drawn that covers most of the cell and lies inside the table, whether the PDF drew it for the cell, the row, the column or the whole table; the colours of the table's own fills, and the soft edge where they meet paper or each other, are taken out of the page picture (`leftovers` in `page.py`). Whatever else is inside a table (a bar across several days, an icon, the part of a shaded row that has no cell) stays a picture behind the table at its place on the sheet (`under_table` in `convert.py`). Strokes and thin bars that are not a border or an underline (a signature line, a separator) are line shapes anchored to the sheet at their place, touching pieces joined into one; a border of a table or box, anything inside a table, and anything inside a picture is not written again (`free` in `convert_page`). A bar at most 6 pt thick along the whole of one edge of a box, over it or just outside it (the box then reaches out to it), is that side of the box's border (`edge_bars` in `page.py`). A rule below everything else on the page is a line shape on the sheet and not a paragraph with a long space before it, which a page that comes out a little taller in Word would push onto a new sheet. A box with rounded corners (four quarter-circle curves of at least 3 pt, `corner_radius` in `shapes.py`) keeps its text in the one-cell table with no fill or border of its own and has a `roundRect` shape behind it with the box's fill and border, anchored in a paragraph just above the box so that it moves with the box's text (`shape_xml` in `builder.py`); a rounded box inside a table cell stays square, and on a design page the page's own picture already has the corners. A picture that a filled shape is drawn over later, such as a caption band, is cut from the rendered page instead of taken from the file, which has no band (`overdrawn` in `page.py`, from the page's bbox log). The gap between a rule and its text is the table's cell padding, and what the cells of a table share (the rule, a shaded header row, stripes, a first column) is written once as a table style, `PDF Table 1` and so on in `styles.xml` (`table_look` in `shapes.py`, `table_style` in `structure.py`), so a cell states only what differs from it, the header row repeats on the next sheet, and Word's Table Design boxes (Header Row, Banded Rows, First Column) and its gallery work on it. The margins are also written on the table, so that they stay when another design is chosen. A cell with nothing in it that is tall enough for a line holds an ordinary empty paragraph, so text typed there shows and the row grows (`blank` in `builder.py`). A centred paragraph gets no first-line or hanging indent. Letter spacing is read from where the letters of a span start, which `read_lines` keeps from PyMuPDF's raw text (`letter_step` in `page.py`): the median over neighbouring letters of the step minus the letter's own width, written only when two letters agree within 0.1 pt, and never from the span's box, which holds a removed list marker, trailing spaces and side bearings. A frame that holds one line has no width, so Word sizes it to its text; a frame or a text box of several lines is as wide as the longest line plus the letter spacing written and 3 pt (`spacing_written` in `builder.py`). A text, a run of leader characters and a short end piece, or a dotted or dashed stroke on the baseline between two pieces of a row, is a paragraph with a right tab that carries the leader, so it cannot wrap when Word sets the text a little wider (`split_leader` in `lines.py`, `stroke_leaders` in `page.py`); the leader characters are not written, and such a line is not a short piece when the page class is chosen. A page longer than 22 inches (1584 pt) on a side is placed, scaled to fit with its proportions, on a page of that size before anything is read (`fit_sheets` in `convert.py`), so its text is still text and its links stay, and its annotations print only through the picture. The last letter of a letter-spaced line that fills its cell is a run of its own without the spacing, which Word adds after the last letter and wraps on (`span_run` in `page.py`). Outlined boxes with a gap between them stay separate boxes with four sides, not the rows of one table (`stripes` in `builder.py`), and the edge of an outlined box is not also written as a rule. A number that opens a paragraph whose next line starts under the number, as in `(1) The Supplier ...`, is text, not a list item (`hangs` in `lines.py`). A bullet is made only of bullet characters, and the letter `o` counts only on its own, so a line that starts with `of`, `on`, `or` or `one`, or a first cell such as `-sU `, keeps its text and is not joined to the cell beside it (`bullet` in `lines.py`). Running text in two or three columns is a continuous section with Word columns, with a column break in a paragraph of its own where the columns end at different heights (`column_runs`, `settle`, `numbered` and `columns` in `builder.py`, `end_sections` in `convert.py`); a large letter beside the first lines of a paragraph is a Word drop capital (`capped` and `drop_cap` in `builder.py`, kept apart from the line beside it by `is_drop_cap` in `lines.py`); a page can therefore hold several sections, `convert_page` returns the header and footer of each, and `attach` in `structure.py` gives references only where they change. A page set freely over pictures and colour is a design page (`page_kind` in `page.py`) and has no flow: `design_page` in `convert.py` renders the page without its text as one picture behind everything and writes each paragraph as a text box anchored to the sheet (`text_boxes` in `builder.py`). The boxes are written in the order the PDF wrote the text when that reads like a page, at least 80 % of the steps going down, along a row or on to the right (`written_order`, from the place each line has in the PDF, `seq` in `lines.py`), because Word prints text boxes in the order they stand in the file; otherwise they are in a geometric reading order (`reading_order`). A table on a design page is a Word table placed on the sheet (`placed` in `table` in `builder.py`: `tblpPr` anchored to the page, overlap allowed, rows `atLeast`, a single line no taller than the table's shortest row, because Word's own line height for the font can exceed the PDF's row pitch): a ruled table comes from `tables` in `page.py`, three or more rows of text that line up in the same columns with no ruling and that the PDF wrote as one text block come from `aligned_tables`, and the rules and cell colours the table paints itself are taken out of the page picture when `table_art` can tell them from the rest of the drawing, otherwise the page keeps them and the table has no borders or shading. On a flowing page, lines side by side that the PDF wrote across, a label and then its value, are one tabbed paragraph a row, and lines that it wrote down one column and then down the next are the cells of one row, however wide each line is, so Word reads them in the PDF's order (`across` and `laid` in `builder.py`). A line of text turned at any angle, a side label or a stamp, is a text box turned by the same angle and anchored to the sheet, on any page (`turned_text_box` in `builder.py`), and is taken out of the picture it was part of, so what surrounds it, such as a stamp's frame and colour, stays in the picture and the words are text on top (`mark_text` in `convert.py`). A paragraph that wraps in places and has a line break in others (an abstract above its keywords) has the width of the PDF's lines as its right indent, so Word wraps it in the same places (`reflow` in `para_xml`). A line ends where the PDF's does unless the paragraph is justified, and a left-aligned box does not wrap, so a wider substitute font cannot break a line; text that is only pixels in a picture stays in the picture. A scanned page, a page stored sideways and a page with no text stay document pages. `pdf_to_docx.py` hands `convert` the original PDF beside the OCR copy (`original`), because the copy holds only the recognised text: for a page that needed OCR, the picture of the scan is rendered from the original, the lines that become text are painted out of it in the colour of the paper around each (`scan_page` and `paper` in `convert.py`; a line is cut a little higher than its box by up to 1.5 % of its width, because OCR text sits at the foot of the box of a skewed line), and it lies behind the text as a picture the size of the sheet. A line larger than 1.6 times the body size, a logo, a signature, a stamp or a large heading, is not text and stays in the picture, and so do the rules and the paper. Recognised text has no font: it is set in the default family and is not bold. A line in the top or bottom tenth of the sheet whose text repeats on at least three quarters of the pages, with the numbers that are the page number and the page count read as `PAGE` and `NUMPAGES` fields, is not written in the page: it is a framed paragraph in a header or footer part (`Furniture` in `structure.py`), and a section carries references only where its header or footer differs from the section before it. A picture of the same image at the same place (within 2 points) in the top or bottom tenth of at least three quarters of the pages is written once in the header or footer part, anchored to the sheet and related from the part (`logo` in `Furniture`, `attach` in `structure.py`), and is left out of those pages. A header or footer in a table, a box or a design page, and one whose numbers are not the page number, stays where it is. The styles are written by `set_styles` in `structure.py` with no look of their own, so a run states its font and size only where they differ from Normal (`span_run` in `page.py`): a heading is Heading 1 to 3 by its size unless it is spoken or signed text: more than two lines or twelve words, a quotation mark at either end, a sentence of more than six words that ends in a full stop, or a name of up to three words under a closing such as `Yours sincerely` (`said` in `builder.py`); the first large heading of the first page is Title, a short bold line of body size on its own above plain text, outside a table or a design page, is Heading 3 (`labels` in `builder.py`), a list item is List Paragraph and a line such as `Figure 1. ...` is Caption (`para_xml` in `builder.py`). A paragraph's lines are `atLeast` the PDF's pitch where Word's own height for the font (`line_height` in `pdf_fonts.py` reads the ascent, descent and line gap from the installed font, which is how Word sizes a line) is no taller, or where the pitch is 1.32 times the size or more, so they make room when the text is made larger (`line_rule` in `builder.py`). Where the PDF sets them tighter than the font, where sizes in the paragraph differ by more than 8 %, where the text is not Latin or where the font is not installed, a paragraph that is not placed is a multiple of Word's own line height (`auto`, so it follows a change of font size) and one in a text box or a row of a placed table is `exact`. LibreOffice sizes a line differently from Word, so lines set as a multiple can sit a little apart there. A line that ends at the hyphen of a word the text spells with a hyphen elsewhere keeps it when Word sets the paragraph again (`compound` in `builder.py`). The paragraph that closes the last page is an ordinary empty paragraph, so text typed at the end of the document has the body size; the closing paragraphs of the other pages are one point high because they end a section (`close_page` in `convert.py`). Every drawing id in the document comes from one counter (`Lists.drawing_ids`), so no two pictures or text boxes share an id however many there are on a page. If the sections a page adds ever differ in number from its header and footer states, `convert` pads or trims the states and `attach` puts the header and footer in the first section, and both log it, so the lines taken out of the pages are not lost. `POMELO_DEBUG=1` prints each paragraph's alignment and whether each page is a design page or a document page (`page_kind` in `page.py`) and which order a design page's text boxes are in. It also lists the figures found inside tables and every line of light text that has no cell fill, box fill, highlight or picture under it (`light_text_check` in `convert.py`), because Word has no page behind the text and such a line would print white on white. Text the PDF does not show is kept as hidden text (`w:vanish`), so the page looks as the PDF does and the words are still in the file: text in the invisible render mode, text under an opaque rectangle drawn after it, and text in the colour of the flat ground under it (`hide` in `page.py`, found from the text trace, the drawing order and the page with that text taken away). A line with only hidden text is not part of the layout (it cannot move visible text or change the page's class) and is written as hidden paragraphs at the end of the page (`hidden` in `builder.py`). Text in a clip render mode paints nothing itself and is not in the trace: the picture shows through its letters, so it is not read and stays in the picture. A page that is one big picture is a scan and has none of this: its invisible text layer is skipped. Every upright line is taken out of the picture the turned text of a stamp or watermark is cut from, wherever the turned word's bounding box lies, so a watermark across a paragraph does not leave the paragraph printed twice.

## How a helper runs

Every entry point starts with `import helper`, then `helper.require(...)` for the packages it needs, then runs `main()` under `if __name__ == "__main__"`. For a PDF, `helper.run_pdf_job(src, work)` does the common part: a scan is read with OCR first (the first 70 % of the progress bar), `work(path, progress)` runs on the PDF, a failure becomes a one-line reason, and the temporary OCR copy is deleted. `work` must close every document it opens before it returns, because Windows will not delete a file that is still open.

## Contracts

The Node side depends on these (`test/integration/python/cli-contract.test.js` checks them):

- Arguments as in the table.
- `POMELO_PROGRESS <0..1>` lines on stdout while it works, and `OK` at the end.
- On failure, one line on stderr and an exit code: 1 failed, 2 a component is not installed, 3 the PDF has no text to convert.
- The messages for a password-protected, a damaged and a page-less PDF, and for a scan when OCR is not installed. The tests assert on them.

## Testing

`node test/run.js --tier=pdf` (needs the PDF engine): the command-line contract, the Word layout checks (`pdf-layout`), and the other formats (`pdf-formats`). For real pages, `npm run test:fidelity` scores PDF to Word against `test/fidelity/baseline.json`; any change to `pdf_flow/` must leave every sample's score equal. `node test/fidelity/run.js --word` does the same comparison with Microsoft Word as the renderer (see `test/README.md`).

## Known limits

- Text in columns is written as Word columns only when it stands in two or three columns with the same gutter, holding lines, inline pictures, tables, boxes, centred captions and equations with their number; anything that crosses a gutter ends the run, and columns beside a rule stay table cells. Columns that end within one and a half lines of each other are left to Word to balance, so text typed at the foot of one runs on into the next; columns that end at different heights keep a column break, and text typed there does not run on.
- A drop capital is a Word drop capital only on a page of running text. On a page set freely over pictures it stays a text box at its place, because Word does not wrap text round a drop capital inside a text box.
- On a design page, a table with no ruling is found only when its rows share one PDF text block and every cell starts at a left edge shared by three lines; a row whose text runs into the next column, or whose first cell was joined to the next one as if it were a list marker, stays a text box and ends the table. Word prints the text of a placed table before the page's text boxes, so a text-order check reads it first. A page that is flowing text and stands sideways (`turned_page`) is read top to bottom, so a form the PDF wrote in another order, with its signature line before its fields, is read in the page's order and not the PDF's. A row added to a table that sits on a coloured panel extends past the panel, and the new row has no panel colour under it. Text drawn with transparency, such as a stamp or a watermark, keeps its transparency in Word 2010 and later (`w14:textFill` with an alpha, which older readers ignore), and a translucent fill over paper or a flat colour is written as the colour it makes there, since cell and box shading has no transparency (`blend` in `page.py`); a fill under a quarter opaque is a shadow or a glow and stays in the picture, and so does a fill over a picture or over a ground that is not flat (`blend` drops it from the shapes, so it is neither a box nor a table). Text in a Type3 font, which has no font name, is written in the default face, so a bold sans heading in such a font comes out in a plain serif.
- A header or footer moves into its part only when it is the same on most pages: one that is not, or whose number is not the page number, stays on the page, and so does a logo that moves, or one that sits in a table, a box or a design page. A part holds the value of one page in its page field, so a reader that does not work fields out shows that number on every page; Word works it out when it prints.
- On a document page, chart labels and the labels of small pictures stay inside the picture, so a word count on the printed Word file does not see them.

- Rules and art behind a table are anchored to the sheet, so they stay put when the text above them is edited.
- Text outside the page is not read (PyMuPDF does not return it), so it is not kept as hidden text. Art inside a table does not move with the table when the text above it is edited, because it is anchored to the page.
- On a scanned page the logo, the signature and any line larger than 1.6 times the body size stay pixels in the picture and cannot be edited, and the text that is written is in the default font and not bold, whatever the scan shows. A PDF whose scan already carries an invisible text layer is not rebuilt this way: that text is skipped as invisible, so its page is the picture alone.
- The Word and the text/Markdown readers each have their own line pipeline, tuned differently (`dedupe` tolerance 3 versus 4 points, different bullet sets), so their output differs in small ways on purpose.
